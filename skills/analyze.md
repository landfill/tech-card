# Analyze
수집된 raw 항목(제목, url, summary, published, source_id)을 다음 카테고리로 분류하라.
**입력으로 전달된 항목만 분류·출력할 것. 목록에 없는 뉴스·발표·URL은 절대 추가하지 말 것.**
**이 뉴스레터의 핵심 범위는 AI agentic coding, AI 개발자 도구, 프론티어 모델, 그리고 이들과 직접 연결된 인프라·산업 적용이다. 이 범위와 직접 관련이 없는 항목은 억지로 분류하지 말고 출력에서 제외하라.**

- 에이전틱 코딩 & 프론티어 모델 (Claude Code, Cursor, Codex, Composer 등)
- GitHub & 인프라 트렌드 (AI 개발자 도구·코딩 에이전트·Copilot·MCP·AI 워크플로와 직접 연결된 CI/CD, 오픈소스, 인프라)
- 산업별 AX (트래블, 금융, 제조 등 산업별 AI·경험. 단, 해당 산업의 AI/LLM/에이전트/자율시스템/자동화 적용이 명시된 항목만 포함)
- 대한민국 IT (한국 기업·정책·시장·국내 언론·국산 기술 관련)

각 항목에 제목, 요약, 출처(url), 카테고리, 영향도(high/medium/low)를 부여하라. JSON 배열로 출력하라.

추가 지침(명시적 규칙 — 반드시 준수):
0. 관련도 필터(가장 중요): 일반 과학, 일반 하드웨어, 일반 웹사이트, 일반 오픈소스/프로그래밍 언어, 일반 보안·보건·항공·제조·금융 뉴스는 AI agentic coding/AI 개발자 도구/프론티어 모델/명시적 산업 AI 적용과 직접 연결되지 않으면 출력하지 말 것.
   - 산업별 AX는 “산업 뉴스” 카테고리가 아니다. AI, LLM, 에이전트, 자율주행/로보틱스, 알고리듬 의사결정, 자동화된 고객/직원 경험처럼 AI 적용이 본문에 명확히 있어야 한다.
   - GitHub & 인프라 트렌드는 “개발 일반” 카테고리가 아니다. AI 코딩 도구, AI 워크플로, Copilot/agent, MCP, 모델 API/SDK, AI 개발 인프라와 직접 관련되어야 한다.
   - 애매하면 포함하지 말고 제외하라. 품질을 위해 항목 수가 적어져도 괜찮다.
1. 오래된 콘텐츠(stale): published 필드 기준으로 현재 시점에서 90일(약 3개월)보다 오래된 항목은 출력하되 영향도(impact)를 반드시 "low"로 설정하고, 요약(summary) 앞에 "[stale]"을 한 칸 띄워 붙여라(예: "[stale] 이 글은 ...").
2. 뉴스레터 렌더링 규격: summary 필드 문자열은 반드시 제목 다음 줄로 렌더링되도록 summary의 시작에 한 줄 바꿈 문자(\n)를 포함시켜라(즉 summary 값은 "\n"으로 시작). JSON 이스케이프 규칙을 준수하라.
3. 무의미한 마무리(예: "— 끝 —", "끝") 처리: summary가 오로지 마무리 표기(또는 그와 유사한 불필요한 문구)로만 구성된 경우, 해당 문구는 제거하고 summary를 빈 문자열("")로 설정하되 영향을 "low"로 지정하라. 요약이 약간의 정보는 포함하나 끝맺음 표기가 혼재하는 경우에는 해당 마무리 표기만 삭제하고 유의미한 부분만 남겨라.
4. 정보 가치가 거의 없는 카드·페이지: 입력 항목 중 실제로 내용(핵심 정보, 데이터, 인사이트)이 거의 없는 '구조적' 페이지(예: 카드뉴스의 마지막 마무리 카드 등)는 제거하지 말고 그대로 출력하되 summary를 가능한 간결하게 정리하고(필요시 빈 문자열), 영향도는 "low"로 설정하라.
5. 출력 형식(스키마)은 절대 변경하지 말 것: 각 객체는 반드시 title, summary, url, category, impact(값: high|medium|low) 필드를 포함하는 JSON 배열로만 응답하라.

예시(형식 참고, 실제 출력은 입력 항목에 따라 달라짐):
[
  {
    "title": "예시 제목",
    "summary": "\n요약 문장 시작...",
    "url": "https://example.com",
    "category": "에이전틱 코딩 & 프론티어 모델",
    "impact": "medium"
  }
]
